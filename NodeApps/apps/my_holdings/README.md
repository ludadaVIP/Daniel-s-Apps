# My Holdings · 持仓室

NodeApps 中的个人投资记录工具。运行 NodeApps 的 `npm run dev` / `start.command` / `start.bat`，在首页选择 **My Holdings**。

## 设计与功能

- **持仓与买入**：点击「记录买入」，填写本次买入股数、单价、可选费用和日期。同一账户、代码（忽略大小写和首尾空格）、币种自动合并，股数累加、总成本累加，成本均价按累计总成本 ÷ 总股数计算，保留完整精度；不同账户或币种分别保留。保存前实时预览合并后的股数和成本。市值沿用该证券最新已保存报价；没有报价时按买入价暂估并明确标记待刷新，避免用 0 价格制造亏损 100%。买入通过串行 API 保存，并防止相同请求重复计入；不会自动扣减手工资金台账。「修正持仓」用于纠正已有总数和成本，区别于追加买入。侧栏可查看最近 8 笔买入或合并前记录，完整记录保存在 `state.json` 的 `holdingTrades` 中。
- **已有重复项**：启动时自动合并同账户、同代码和币种的重复持仓，按原始总成本相加，采用有效报价重新计算市值。合并前的每条原始记录保留在 `holdingTrades`，并沿用自动备份；跨账户不合并。恢复旧备份时采用相同规则。通用持仓编辑接口拒绝制造重复项。
- **价格刷新**：点击「刷新价格」只加入 Codex 待办。Codex 实际开始取价时先调用 `POST /my-holdings/api/jobs/{id}/quote-policy`，服务端保存执行时间并返回取价规则：美股常规交易时段取最新可核验盘中价，其余时间取最近已完成交易日正式收盘价（收市后包含当天）。使用 `America/New_York` 时区，处理夏令时、周末、法定休市与提前收市，日历依据 [NYSE 官方日历](https://www.nyse.com/trade/hours-calendars)；临时休市须核实公告并维护 `server/market-session.js` 的例外表，无法核实则标记未完成。回写时带 `executedAt` 及所有代码的 `price/date/type/source/sourceUrl`；盘中价必须提供来源的 UTC 报价时间 `asOf`，最多允许 20 分钟延迟，不能用旧收盘价替代。服务端校验全部报价后，按价格 × 股数更新市值，保留成本均价和总成本；界面标明盘中价或收盘价、日期、报价时间（美东）与来源，失败时保留原价格。
- **近期关注**：输入公司名或代码即可保存，新标的自动加入价格更新和首次研究待办。「刷新关注」更新全部标的价格，逐个建立 `watch-quotes` 任务，采用与持仓相同的执行时刻 `quote-policy`：常规交易时段取盘中价，其他时间取最近已完成交易日收盘价。报价保留类型、实际时间、币种与来源；价格任务无需 HTML，不能修改既有研究、报告或研究日期，单个失败不影响其他标的。SPYL、CNDX 等已确认 LSE 上市的标的按伦敦交易日历和 Europe/London 时区取价（包含收盘集合竞价），不套用美股盘中状态；其余采用美股时段。只有缺少完整研究（`research.details` 或报告路径为空）的标的才额外建立 `watch` 首次研究任务；执行时若已补齐则跳过。已有完整研究只在明确点击「更新完整研究」或请求 `refreshResearch: true` 时重做。报告中的历史报价不会覆盖独立刷新后的行情。再次点击可撤销本次仍未开始的任务，保留已有待办及已开始任务。应用不会启动 Codex CLI、自动联网或占用额度；也能复制资料给其他 AI。
- **换算工具**：用 VOO→SPYL（S&P 500）和 QQQM→CNDX（Nasdaq-100）两组 USD 挂牌产品做短期价格参照。输入任意一边的价格即可换算；更新公式会采集最近 10 个共同交易日、伦敦时间 16:25 附近的同步盘中价格，以配对比值中位数计算中心值、P25–P75 作为近期典型参考带。数据源支持同步盘口价、一分钟线或同一时点收盘的五分钟线；无法核实同步数据时保留旧公式。
- **组合分析 / 行情研究**：点击请求后加入待办，界面显示等待、完成或未完成。选择「复制待办给 Codex」后，把提示粘贴给 Codex；Codex 可读取队列、联网研究、生成 HTML 并回写结果。
- **弹药与目标**：资金流水只使用 USD；目标用一段自由文本记录。资金是个人手工台账，不等于券商实时余额。
- **行情与档案**：把独立 HTML 保存到 `data/reports/market/`、`portfolio/` 或 `research/`。点击档案卡片会在新的浏览器标签页打开 HTML 原件，不在应用中预览。
- **其他**：组合集中度和压力情景本地计算、跨 AI 复制背景、导入 AI 研究 JSON/HTML、决策日志、左右侧栏独立折叠。

## 数据与 GitHub 同步

所有业务数据都保存在本目录文件里，不存在浏览器 `localStorage`：

- `data/state.json`：持仓、关注、资金、目标、Codex 待办和研究摘要。保存时创建 revision 并原子写入。
- `data/CODEX_TODO.md`：由应用维护的待办说明，适合 Codex 读取，也会随 Git 同步。
- `data/backups/`：最近 30 次修改前的 JSON 备份。
- `data/reports/`：HTML 研究报告原件和 VisualShelf 目录。
- `data/initial-state.json`：首次启动的种子数据，不覆盖日常状态。
- `account1.jpg`、`account2.jpg` 与 `holdings-transcription.md`：原始截图和逐字段转录。

这些文件在 NodeApps 仓库中跟踪，正常 Git 提交与 GitHub 同步即可在不同电脑间迁移。切换电脑前先同步提交，另一台先拉取再打开应用；避免两台电脑同时修改同一个 `state.json`，以免产生 Git 文件冲突。浏览器只记住左右栏展开偏好，不存持仓等业务数据。

## Codex 待办的执行方式

关注、价格或分析请求会记录在 `state.json` 的 `jobs` 中，状态为 `waiting`；`data/CODEX_TODO.md` 也列出等待任务。应用不会自动调用 Codex。需要时在 Codex 中粘贴应用复制的待办指令；研究完成后将 HTML 放进对应报告目录并调用 `/my-holdings/api/jobs/{id}/complete` 回写结果。价格任务先调用 `quote-policy` 再取价，完成时原样提交其 `executedAt` 和 `quotes`，不用生成 HTML；重新取价须重新获取 policy，旧执行批次不能覆盖新批次。换算公式任务不用生成 HTML，向同一端点提交两组 `calibrations`，服务端会校验 10 天的 UTC 同步样本和行情来源，再重算中位数与 P25–P75 参考带；无法完成则回写 `fail` 并保留旧公式。若本地应用没运行，价格任务须保留待办，待启动服务取得执行时刻 policy 后再取价；其他任务可更新 `state.json` 并说明无法自动刷新页面。
