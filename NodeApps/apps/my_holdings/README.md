# My Holdings · 持仓室

NodeApps 中的个人投资记录工具。运行 NodeApps 的 `npm run dev` / `start.command` / `start.bat`，在首页选择 **My Holdings**。

## 设计与功能

- **持仓与买入**：点击「记录买入」，填写本次买入股数、单价、可选费用和日期。同一账户、代码（忽略大小写和首尾空格）、币种自动合并，股数累加、总成本累加，成本均价按累计总成本 ÷ 总股数计算，保留完整精度；不同账户或币种分别保留。保存前实时预览合并后的股数和成本。市值沿用该证券最新已保存报价；没有报价时按买入价暂估并明确标记待刷新，避免用 0 价格制造亏损 100%。买入通过串行 API 保存，并防止相同请求重复计入；不会自动修改可部署资金流水或账户现金快照。「修正持仓」用于纠正已有总数和成本，区别于追加买入。侧栏可查看最近 8 笔买入或合并前记录，完整记录保存在 `state.json` 的 `holdingTrades` 中。
- **账户现金持仓**：在各账户卡片中独立录入 USD 现金余额快照。账户现金计入总资产、现金 / 证券占比和金额目标进度；编辑后不会自动跟随买入或资金流水变化。它与「可部署弹药」分开管理，后者仍只按独立资金流水和预留金额计算。
- **已有重复项**：启动时自动合并同账户、同代码和币种的重复持仓，按原始总成本相加，采用有效报价重新计算市值。合并前的每条原始记录保留在 `holdingTrades`，并沿用自动备份；跨账户不合并。恢复旧备份时采用相同规则。通用持仓编辑接口拒绝制造重复项。
- **价格刷新**：点击「刷新价格」只加入 Codex 待办。Codex 实际开始取价时先调用 `POST /my-holdings/api/jobs/{id}/quote-policy`，服务端保存执行时间并返回时区、session、报价日期与最近可用收盘日。必须照 `America/New_York` 时区处理美股夏令时、周末、法定休市与提前收市，不能把“常规交易所已收市”当成“没有交易”；新西兰周五白天可能对应美东周四夜盘。美股优先核实 Moomoo 报价页或本机 Moomoo OpenAPI：按实际 session 读取 `last_price`、`pre_price`、`after_price` 或 `overnight_price`，同时读取报价 `update_time`（美东）并换算 UTC；可用 `get_market_state` 核验证券是否处于目标时段。OpenAPI 仅使用 Quote API，不调用任何交易接口。Moomoo 夜盘为美东 20:00–次日 04:00，交易日期属于次一交易日（T+1）；夜盘 `asOf` 可落在前一美东自然日，但 `date` 使用 policy.date。具体证券仍要确认支持该时段。若 Moomoo 不可用或没有新鲜夜盘价，查 TradingView BOATS 24/5 夜盘图表，核对 Blue Ocean Alternative Trade System、Market open、当前价及 UTC 时钟；官方说明夜盘数据实时提供、图表每秒更新。之后再查其他能明确显示同一时段及时间戳的来源；不能只查 Yahoo 或普通常规盘报价后就回退。实时/延长报价必须与 policy.session 一致、报价时间距执行时刻不超过 20 分钟且可核验；否则才回退到 `policy.fallbackDate` 最近已完成交易日正式未复权收盘价。周末/休市日的回退日以服务端 policy 为准，通常为周五。日历依据 [NYSE 官方日历](https://www.nyse.com/trade/hours-calendars)；临时休市须核实公告并维护 `server/market-session.js` 的例外表。回写时带 `executedAt` 及代码的 `price/date/type/source/sourceUrl`；实时/延长价还需 `session` 和真实 UTC `asOf`。服务端校验后按价格 × 股数更新市值，保留成本均价和总成本；界面标明报价类型、日期、报价时间（美东）与来源，失败时保留原价格。
- **手动改价**：在持仓表点击「当前价格」数字，可录入盘后参考价、手动盘中价或其他手工价格及对应交易日。保存后按持仓股数重算市值，成本不变；报价会标记为手动调整，并清除旧的自动报价时间和来源链接。
- **近期关注**：输入公司名或代码即可保存，新标的自动加入价格更新和首次研究待办。「刷新关注」更新全部标的价格，逐个建立 `watch-quotes` 任务，使用与持仓相同的执行时刻 `quote-policy` 和实时源优先级：美股常规、盘前、盘后或夜盘都先核实对应 session 的实时报价；夜盘优先核对 Moomoo 与 TradingView BOATS，只有没有 20 分钟内可核验报价时才回退收盘价。报价保留类型、实际时间、币种与来源；价格任务无需 HTML，不能修改既有研究、报告或研究日期，单个失败不影响其他标的。SPYL、CNDX 等已确认 LSE 上市的标的按伦敦交易日历和 Europe/London 时区取价（包含收盘集合竞价），不套用美股 session；其余采用美股时段。只有缺少完整研究（`research.details` 或报告路径为空）的标的才额外建立 `watch` 首次研究任务；执行时若已补齐则跳过。已有完整研究只在明确点击「更新完整研究」或请求 `refreshResearch: true` 时重做。报告中的历史报价不会覆盖独立刷新后的行情。再次点击可撤销本次仍未开始的任务，保留已有待办及已开始任务。应用不会启动 Codex CLI、自动联网或占用额度；也能复制资料给其他 AI。
- **换算工具**：用 VOO→SPYL（S&P 500）和 QQQM→CNDX（Nasdaq-100）两组 USD 挂牌产品做短期价格参照。输入任意一边的价格即可换算；更新公式会采集最近 10 个共同交易日、伦敦时间 16:25 附近的同步盘中价格，以配对比值中位数计算中心值、P25–P75 作为近期典型参考带。数据源支持同步盘口价、一分钟线或同一时点收盘的五分钟线；无法核实同步数据时保留旧公式。
- **组合分析 / 行情研究**：点击请求后加入待办，界面显示等待、完成或未完成。选择「复制待办给 Codex」后，把提示粘贴给 Codex；Codex 可读取队列、联网研究、生成 HTML 并回写结果。
- **弹药与目标**：资金流水只使用 USD；目标用一段自由文本记录。可部署弹药是独立手工资金池，不等于券商实时余额，也不包含单独录入的账户现金余额。
- **委托单**：在「弹药与目标」页维护本地潜在订单台账，可关联近期关注，按卡片或列表查看，并按剩余金额、代码、状态或提交时间排序。记录方向、交易所、限价 / 市价、委托与已成交数量、有效期、台账与券商状态、原始显示时间、账户和备注；汇总仅估算未成交买入限价金额，不表示资金已被券商冻结。台账不会连接或操作券商；旧备份缺少委托字段时按空记录恢复。
- **行情与档案**：把独立 HTML 保存到 `data/reports/market/`、`portfolio/` 或 `research/`。点击档案卡片会在新的浏览器标签页打开 HTML 原件，不在应用中预览。
- **其他**：组合集中度和压力情景本地计算、跨 AI 复制背景、导入 AI 研究 JSON/HTML、决策日志、左右侧栏独立折叠。

## 个股穿透

「我的持仓」下方展示公司敞口前十名，可查看全部账户或单个账户，展开每家公司可见各基金和直接持股的贡献金额。计算使用**完整基金成分表**后再排序，支持 VOO、QQQM、SOXX、SMH、VGT；未持有 VGT 时不计入结果，未来录入买入后自动参与。GOOG / GOOGL 等同一公司多类股合并，直接持股与 ETF 间接持股也合并。

`公司敞口（USD）= Σ（基金持仓市值折算 USD × 该公司所有股类的基金权重 ÷ 100）+ 直接持股市值折算 USD`。持仓市值按股数 × 当前保存的报价重新计算，逐笔保留到分；公司占比以所选范围的总资产为分母：全部账户视图包含证券、各账户现金与独立可部署弹药；单个账户视图包含该账户证券与现金。搜索持仓不会截断穿透范围。数量、报价或汇率变化立即在本地重算，不需要联网或重新研究；缺少汇率的持仓会明确列为未计入。

权重快照单独保存在 `data/fund-holdings.json`，通过只读 `GET /my-holdings/api/fund-holdings` 每次进入持仓页读取，无需重启服务或改动 `state.json`；基金全量披露不会重复塞进每次状态备份。原始网页、下载与截图等本地核验资料位于 `artifacts/my-holdings-lookthrough-2026-10-27/`，由 `.gitignore` 排除，不进入 Git 同步；这些文件可能包含第三方站点内嵌凭据，不应原样提交。应用仅依赖经过整理的正式权重 JSON，其官方来源、日期和原始证据摘要保留在文件内。初次数据来自 Vanguard 官方接口（VOO、VGT，截至 2026-09-30）、Invesco 官方接口（QQQM，截至 2026-10-23）、BlackRock 官方 CSV（SOXX，截至 2026-10-23）及 VanEck 官方完整持仓表（SMH，截至 2026-10-23）。这些是**披露权重估算**，不是实时基金账本，也不是可直接卖出的个股股数。

股票只计入 `assetType: "equity"` 的持仓。现金、货币基金（例如 SOXX 中的 XTSLA）、保证金、期货、其他衍生品及 CVR 权利单独保存，不分配为普通股票。期货的净值权重与名义敞口不同，本视图未做衍生品底层股票分解。未知权重保留 `null`；发行商权重未经归一化，股票合计可能因负现金或精度略超过 100%。「基金非股票与披露差额」为总持仓减去已识别公司和未穿透基金的余额，包含非股票工具与披露舍入差额。新出现且未提供成分的 ETF 会明确标记未穿透，避免当作一家普通公司。

点击「复制复核任务」后粘贴给 Codex 即可更新权重，应用不会自行联网。复核时保留每只基金真实 `asOf`、`retrievedAt`、官方 HTTPS 来源、`complete: true`、全部成分和原始权重精度；不同日期允许并列，不得把抓取日期当成分日期。新数据必须先通过 `validateFundHoldings` 与 `node --test apps/my_holdings/src/lookthrough.test.js`，再原子替换 JSON 文件并读取 API 确认。获取失败的基金保留旧数据。披露超过 45 天显示「建议复核」。修改后重新进入持仓页即可读取最新快照。

## 数据与 GitHub 同步

所有业务数据都保存在本目录文件里，不存在浏览器 `localStorage`：

- `data/state.json`：持仓、关注、资金、目标、Codex 待办和研究摘要。有效变更立即创建 revision、刷盘后原子写入；内容未变化时不增加版本。
- `data/fund-holdings.json`：有日期和官方来源的全量基金成分权重，供个股穿透使用，独立于持仓状态快照。
- `data/CODEX_TODO.md`：由应用维护的待办说明，适合 Codex 读取，也会随 Git 同步。
- `data/backups/`：独立可恢复的 `.json.gz` 压缩快照，文件名包含产品、状态更新时间（UTC）和版本号。普通修改每 5 分钟最多建立一个恢复点，只有排名变化不产生备份；持仓、账户、资金、目标和买入记录变化、删除关注/日志以及恢复前立即备份。每次修改仍即时保存到 `state.json`，合并的是备份频率。保留最近 6 份快照、最近 7 个有记录 UTC 日及 4 个有记录 UTC 周的首份快照，重叠只存一份，最多 17 份；每天/每周的起点避免批量误操作挤掉历史。旧 JSON 首次启动时逐份压缩，落盘后解压核对原始字节一致才删除旧文件，再按新规则保留；无法校验的文件保留并记录警告。应用可直接选择 `.json` 或 `.json.gz` 恢复，恢复前的快照带 `before-restore` 标记。
- `data/reports/`：HTML 研究报告原件和 VisualShelf 目录；自动生成的报告名包含报告类型、代码/主题和生成日期。
- `data/initial-state.json`：首次启动的种子数据，不覆盖日常状态。
- `account1.jpg`、`account2.jpg` 与 `holdings-transcription.md`：原始截图和逐字段转录。

这些文件在 NodeApps 仓库中跟踪，正常 Git 提交与 GitHub 同步即可在不同电脑间迁移。切换电脑前先同步提交，另一台先拉取再打开应用；避免两台电脑同时修改同一个 `state.json`，以免产生 Git 文件冲突。浏览器只记住左右栏展开偏好，不存持仓等业务数据。

## Codex 待办的执行方式

关注、价格或分析请求会记录在 `state.json` 的 `jobs` 中，状态为 `waiting`；`data/CODEX_TODO.md` 也列出等待任务。应用不会自动调用 Codex。需要时在 Codex 中粘贴应用复制的待办指令；研究完成后将 HTML 放进对应报告目录并调用 `/my-holdings/api/jobs/{id}/complete` 回写结果。价格任务先调用 `quote-policy` 再取价，完成时原样提交其 `executedAt` 和 `quotes`，不用生成 HTML；重新取价须重新获取 policy，旧执行批次不能覆盖新批次。换算公式任务不用生成 HTML，向同一端点提交两组 `calibrations`，服务端会校验 10 天的 UTC 同步样本和行情来源，再重算中位数与 P25–P75 参考带；无法完成则回写 `fail` 并保留旧公式。若本地应用没运行，价格任务须保留待办，待启动服务取得执行时刻 policy 后再取价；其他任务可更新 `state.json` 并说明无法自动刷新页面。
