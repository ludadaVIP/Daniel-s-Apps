# 估算根式的值

## 精确根式、严格界限与近似值

√2 是精确数，1.41 是有限小数，二者不相等。估算不是改变精确数，而是找到接近它、适合所需精度的表示。可用上下界说明它在哪里，再按规则四舍五入。下界、上界、截断与最近舍入不是同一个概念。

在非负数上，平方保大小顺序，所以 l²<a<u² 且 l,u≥0 时，l<√a<u。必须保留非负条件，不能在整条实数轴上说“平方越大原数就越大”：例如 −3 比 −2 小，平方九却比四大。精确平方给界限，像素点只帮助理解位置，不能代替比较。

### 例 1：√2 的两位舍入，不能只看端点

1.4²=1.96<2<2.25=1.5²，所以1.4<√2<1.5。保留一位小数的舍入中点是1.45，而1.45²=2.1025>2，故√2<1.45，更靠近1.4，一位结果为1.4。

细化到百分位：1.41²=1.9881<2<2.0164=1.42²。这个区间横跨舍入中点1.415，单凭两端还不能判断最近的百分位是哪边。算1.415²=2.002225>2，所以√2<1.415，才确定两位结果为1.41。

写 √2≈1.41，而不是 √2=1.41。不能先把计算器显示截到1.41，再说“因为看到1.41所以舍入1.41”；那把需要证明的信息预先丢掉了。平方夹界与中点比较也能在没有很多显示小数的情况下给出严格依据。

### 例 2：向上舍入、跨整数与精确有限值

对 √50，7.0²=49<50<50.41=7.1²。虽然下界是7.0，舍入中点7.05的平方49.7025<50，根在中点右侧，因此保留一位应取7.1。把前一位截断成7.0会错选方向。

对 √(999/1000)，0.99²=0.9801<0.999<1²。中点0.995²=0.990025<0.999，因此两位舍入跨过整数边界，结果写1.00。所需尾零表示本题要求的两位形式；写1或1.0虽是同一个有理数量，却未满足指定小数位的作答形式。

并非每个根式只能近似：√(25/16)=5/4=1.25，这里可用精确等号。若题目要求保留一位，应再按精确中点1.25处理，本课非负数“四舍五入”中点取较大者，结果1.3。不能因为输入恰为精确数，就忽略题目另问的舍入形式。

## 精度、误差和显示窗口

一格宽度为0.01时，最近百分位舍入的绝对误差不超过0.005；中点恰好相等时按本课规则向上。夹在相邻百分位端点之间只说明区间宽0.01，不能把任一下界的误差自动称为半格。误差大小要对应你采用的输出规则。

探索区可选择被开方数与小数位，先作答，再显示平方界、中点和近似点。改变精度会换题并清旧反馈；主动显隐图形保留作答。精确完全平方的情形会直接标等号，不伪造严格不等式。点是显示近似，根式标签与精确分数比较才是计算依据。

家长请孩子写至少一组真实平方比较并说出中点在哪边，核查≈/＝、尾零及数域。背出一串常见根式小数不等于会估算；能解释为何这一位该向上或向下，才连接了精确结构与近似运算。

# Estimating radical values

## Exact roots, bounds and rounded approximations

√2 is exact; 1.41 is a terminating decimal and a different number. Estimation locates an exact value and selects an approximation at a requested precision. Lower bound, upper bound, truncation and nearest rounding are distinct.

Squaring preserves order on nonnegative numbers. Thus l²<a<u² with l,u≥0 implies l<√a<u. It does not preserve order over all reals: -3<-2 but 9>4. Exact squares establish evidence; pixel placement only illustrates it.

### Example 1: two-place rounding of √2

Since 1.4²=1.96<2<2.25=1.5², the root lies between 1.4 and 1.5. The one-place midpoint 1.45 has square 2.1025>2, so round to 1.4.

At hundredths, 1.41²=1.9881<2<2.0164=1.42². These bounds straddle midpoint 1.415, so alone they do not select the nearer endpoint. Since 1.415²=2.002225>2, the root is below the midpoint and rounds to 1.41.

Write √2≈1.41, not exact equality. Truncating a display first cannot establish the required rounding; it has already discarded information. Squared bounds and midpoint comparisons provide evidence without needing a long decimal display.

### Example 2: round up, cross an integer, recognise exactness

For √50, 49<50<50.41 places it between 7.0 and 7.1. Midpoint 7.05²=49.7025<50 puts the root on the upper side, so the one-place result is 7.1 rather than truncated 7.0.

For √(999/1000), 0.9801<0.999<1 bounds it between 0.99 and 1.00. Midpoint 0.995²=0.990025<0.999 selects 1.00. Keep both requested decimal places; one or 1.0 has the same rational value but not the requested written precision.

Some radical values are exactly terminating: √(25/16)=5/4=1.25. Equality is valid here. If asked instead for one-place rounding, the exact midpoint 1.25 rounds upward to 1.3 under this unit’s nonnegative halfway-up rule.

## Precision and error

Nearest hundredth rounding has absolute error at most 0.005. Merely knowing adjacent hundredth bounds gives an interval of width 0.01; a lower-bound truncation does not automatically have half-grid error. Match the error claim to the output rule.

Choose a radicand and precision before revealing exact squared bounds, the midpoint and an approximate point. Precision changes reset the task; display changes preserve writing. Perfect-square cases use exact equality rather than false strict bounds.

A parent asks for actual squared comparisons, the midpoint side, appropriate ≈ versus =, trailing zeros and the nonnegative domain. Memorised decimals alone do not show how to estimate; explaining the rounding direction connects exact structure with approximation.
